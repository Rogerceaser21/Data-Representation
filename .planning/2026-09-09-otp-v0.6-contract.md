## 1. Scope

1. **Rubric v2 = 32 single-sentence criteria.** `Assets/OTP/rubric-sp1-v2.json` is generated and
   FINAL: every multi-sentence paragraph of `rubric-sp1.json` was split at sentence boundaries,
   wording untouched (Beginner 4, Emerging 5, Good 7, Great 8, Outstanding 8). Each level has
   `paragraphs` (the criteria, in order) and `origins` (source paragraph, `2.1` = paragraph 2
   sentence 1). Criterion numbering `n` = 1-based position within its level IN V2.
   `rubric-sp1.json` (v1, 26 paragraphs) stays in the repo untouched: legacy records render on it.
2. **A note per criterion** (typed, or Apple Pencil through the existing Evidence Pad), a `+`
   button on every chip, an in-place panel, a blue badge when the note is filled.
3. **No numbers, no points.** Colour words + notes are the data. White = not assessed.
4. **Wording** (exact strings in §4).
5. **`rubric_version`** stamped on every submission; records without it render on the v1 layout.

Out of scope: AI drafting of Next Steps (v0.7), the dashboard, any Supabase migration (none is
needed: `ingest_otp` stores the payload verbatim), the R3 form (must stay byte-identical).

## 3. Value formats

- `sp1_<level>`: UNCHANGED format. `"n:<state word>"` tokens joined by `", "`, ascending `n`,
  coloured criteria only; `n` indexes the V2 criteria. State words exactly `present`,
  `partially present`, `not present`. A bare number is a legacy v0.1 value and reads as `present`.
- `sp1_present` / `sp1_partially_present` / `sp1_not_present` / `sp1_not_seen`: UNCHANGED format
  (`"<Level> <n>"` items joined by `", "`, level order then ascending `n`). `sp1_not_seen` lists
  all 32 when nothing is coloured, `""` when all 32 are coloured. The four lists always
  partition the 32 criteria.
- `sp1_selected_text`: one item per criterion that is COLOURED or CARRIES A NOTE, level order
  then ascending `n`, joined by `" | "`:
  `"<Level> <n> (<State>): <criterion text>"` + (note ? `" Note: " + note` : `""`),
  where `<State>` is `Present` / `Partially present` / `Not present`, or `Not assessed` for an
  uncoloured criterion that has a note. Inside this cell a note has its whitespace collapsed to
  single spaces. Empty string when nothing is coloured and no note exists.
- `sp1_notes`: `""` when no criterion has a note; otherwise a JSON object serialised with
  `JSON.stringify`, keys `"<Level> <n>"` in level order then ascending `n`, values = the note text
  (trimmed, internal newlines preserved), non-empty notes only.
  Example: `{"Good 3":"challenge is not provided","Great 5":"students still on SC1"}`.
- `rubric_version`: the literal `sp1-v2` on every v0.6 submission.

## 5. Form (lane A) · `Assets/OTP/src/otp-progress-form.html`

- Inline BOTH rubrics as JS constants: `SP1` = v2 (live), `SP1_V1` = v1 (legacy render only).
  Every rubric routine (`buildRubricTable`, `readRubSelection`, `writeRubSelection`,
  `writeNotSeen`, `syncRubricChips`, the hidden-input lookups) reads the ACTIVE rubric
  (a variable, default `SP1`).
- **`+` note button**: `button.rub-note-btn` as a SIBLING of `.rub-chip` inside `.rub-cell` (never
  nested: a button inside a button is invalid HTML and would break the tap cycle). `type="button"`,
  `data-level`, `data-n`, `aria-label="Add a note for <Level> <n>"` (`"Edit the note for ..."`
  once filled). Visually a 20-22px circle with a `+` glyph at the chip's bottom-right corner;
  hit area at least 36x36px; the chip's text gets enough bottom/right padding that the button
  never covers a word. Empty: muted outline. Filled (`.has-note`): solid AIS blue `#1257FF`,
  white glyph, in light, dark AND print. Tapping `+` never cycles the colour; tapping the chip
  never opens the panel (the row click handler keys on `closest('.rub-chip')`, keep it so).
- **Note panel**: `tr.rub-note-row` inserted directly after the chip's table row, one
  `td[colspan=5]`; at most ONE panel open at a time (opening another closes the first). Contents:
  header `Note · <Level> <n> · <State>` (`<State>` per §3, `Not assessed` when white, updated
  live if the colour changes while the panel is open), the criterion text in small type, a
  `textarea` (id `sp1_note_<level>_<n>`, NO `name` attribute, so it is neither posted nor drafted
  directly), the Evidence Pad pencil (`button.pad-field-btn`) and paperclip (`button.pad-attach`,
  hidden until pages exist) both with `data-pad-target="sp1_<level>_<n>_note"`, and a `Done`
  button that closes the panel. Tapping the same `+` again also closes it. The panel is in
  normal document flow: no `position:fixed`, no scroll locking, no body repositioning, no
  auto-focus on open (Pencil users must not get the keyboard). Do not touch the keyboard engine.
- **Source of truth**: hidden `input[name=sp1_notes]` (§3 JSON) and hidden
  `input[name=rubric_version]` (`sp1-v2`). Every textarea `input` rewrites `sp1_notes`,
  rebuilds `sp1_selected_text`, toggles `.has-note`, and dispatches the same bubbling `change`
  the autosave listens for (mirror `writeRubSelection`). `syncRubricNotes()` reads `sp1_notes`
  and fills textareas + badges; it runs on load, draft restore, record load and reset (mirror
  `syncRubricChips`). A colour change also rebuilds `sp1_selected_text` (notes stay).
- **Draft**: key `ais-otp-form-v1` unchanged. On restore, a draft whose `rubric_version` is not
  `sp1-v2` drops ONLY its `sp1_*` values (chips start clear, `sp1_notes` empty) and keeps every
  other field. A v0.6 draft restores chips + notes + badges.
- **Legacy record render**: `loadClosedRecord` reads `data.rubric_version`; anything other than
  `sp1-v2` rebuilds the rubric table from `SP1_V1` BEFORE populating, so a v0.5 record (paragraph
  numbering) lights the right paragraphs. Notes on legacy records are simply absent.
- **Locked / record view** (`CLOSED_RECORD_VIEW` or `.is-locked`): the `+` badge stays tappable
  to READ; the panel shows the note read-only (textarea `readonly`), pencil hidden, paperclip
  shown when pages exist; nothing writes the draft (hard rule 13 stays).
- **Evidence Pad**: 32 new targets `sp1_<level>_<n>_note` (`<level>` in
  `beginner|emerging|good|great|outstanding`, `<n>` the v2 number), labels `Note · <Level> <n>`,
  slugs `sp1-<level>-<n>-note` (page files `sp1-<level>-<n>-note[-k].jpg`). `TARGETS`,
  `TARGET_LABELS`, `TARGET_SLUGS`, `PAD_SLUG_TARGETS` are GENERATED from the rubric constant, not
  hand-listed. The extract request for a note target additionally sends
  `context` = the criterion text (max 400 chars). On Done the extracted text lands in that
  criterion's note textarea exactly like the five fields (replace-not-duplicate, submit backstop),
  then `sp1_notes`, the badge and `sp1_selected_text` update. Pad page header shows the label.
  Buttons created inside panels must work (bind on creation or delegate).
- **Print**: criteria with notes print as a `Criterion notes` list under the rubric table
  (`<Level> <n> (<State>): note`); open panels need not print.
- `REQUIRED_FIELDS` unchanged (notes optional). Footer `Form · Progress in Lessons OTP · otp-v0.6`.
  `<title>` unchanged. Everything else in the form (Tom Selects, autosave, keyboard engine, pad
  internals, admin cog, fetch resilience) stays byte-identical in behaviour.
- **Docs** (lane A): `Assets/OTP/README.md` header, "What is on the page" item 3, the contract
  key list, the value formats, a `Tests` line if counts change, and a changelog entry.
